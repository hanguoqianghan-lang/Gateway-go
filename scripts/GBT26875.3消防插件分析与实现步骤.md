# GB/T 26875.3-2011 消防插件分析与实现步骤

## 一、协议总体结构

GB/T 26875.3-2011 《城市消防远程监控系统 第3部分：报警传输网络通信协议》规定了"用户信息传输装置 ↔ 监控中心"之间的通信协议。

### 协议栈

```
┌──────────────────────────────┐
│     应用层（本标准定义）        │
├──────────────────────────────┤
│   TCP/IP 或 UDP/IP（RFC）      │
└──────────────────────────────┘
```

### 通信模式（6.1-6.5节）

| 模式 | 方向 | 说明 |
|------|------|------|
| 发送-确认 | 监控中心 → 装置 | 控制命令下发 |
| 发送-确认 | 装置 → 监控中心 | 信息上传（报警、状态） |
| 请求-应答 | 监控中心 → 装置 | 信息查询 |

**重发机制**：超时 ≤ 10s，重发 3 次，校验错误后启动重发。

## 二、数据包结构（表1 — 核心）

```
数据包 = 启动符(2) + 控制单元(25) + 应用数据单元(变长, ≤1024) + 校验和(1) + 结束符(2)
```

| 序号 | 字段 | 字节数 | 说明 |
|------|------|--------|------|
| 1-2 | **启动符** | 2 | 固定值 `0x40 0x40`（即两个 `@@`） |
| 3-4 | **业务流水号** | 2 | 发送端递增，低字节在前，初始值 0 |
| 5-6 | **协议版本号** | 2 | 主版本号(第5字节)固定=1，用户版本号(第6字节)自定义 |
| 7-12 | **时间标签** | 6 | BCD编码：秒(1) 分(1) 时(1) 日(1) 月(1) 年(1)，见 8.2.2 |
| 13-18 | **源地址** | 6 | 低字节在前 |
| 19-24 | **目的地址** | 6 | 低字节在前 |
| 25-26 | **应用数据单元长度** | 2 | ≤1024，低字节在前 |
| 27 | **命令字节** | 1 | 见表2 |
| 28~N-2 | **应用数据单元** | 变长 | 确认/否认包可为空 |
| N-1 | **校验和** | 1 | 控制单元第3~27字节 + 应用数据单元的**算术和**（模256，舍去进位） |
| N | **结束符** | 2 | 固定值 `0x23 0x23`（即两个 `##`） |

### 命令字节定义（表2）

| 值 | 命令 | 说明 |
|----|------|------|
| 0 | 预留 | - |
| **1** | 控制命令 | 时间同步 |
| **2** | 发送数据 | 发送火灾报警和建筑消防设施运行状态等信息 |
| **3** | 确认 | 确认回答 |
| **4** | 请求 | 查询操作 |
| **5** | 应答 | 返回查询信息 |
| **6** | 否认 | 否认回答 |
| 7~127 | 预留 | - |
| 128~255 | 用户自定义 | - |

## 五、报文案例验证

### 案例1：控制命令（时间同步请求）

```
4040 0000 0101 011E16080C15 800D00000000 000000000000 0400 02 19010100 0E 2323
```

| 字段 | 值 | 解析 |
|------|-----|------|
| 帧头 | `40 40` | 启动符 @@ |
| 流水号 | `00 00` | 流水号=0 |
| 版本号 | `01 01` | 协议版1.1 |
| 时间标签 | `01 1E 16 08 0C 15` | 秒=01, 分=30, 时=22, 日=00, 月=0C(12月), 年=15(21年) → 2021年12月16日22:30:01 |
| 源地址 | `80 0D 00 00 00 00` | 源地址=0x00000000000D80 |
| 目的地址 | `00 00 00 00 00 00` | 目的地址=0 |
| 数据长度 | `04 00` | 4字节（注意小端） |
| 命令字节 | `02` | 命令=发送数据 |
| 应用数据 | `19 01 01 00` | 类型0x19=25 + 1个信息对象 + 信息体 |
| 校验和 | `0E` | 控制单元字节和模256 |
| 帧尾 | `23 23` | 结束符 ## |

### 案例2：确认应答

```
4040 0000 0101 001E16080C15 000000000000 800D00000000 0000 03 EF 2323
```

- 命令字 = `03`（确认），应用数据长度 = 0
- 校验和 = 0xEF

### 案例3：上传部件运行状态

```
4040 7D06 0101 22110D0A0915 020000000000 000000000000 3000 02
0201 01 03 00 5001 0100 0500 05 00 0000...0000 00 22110D0A0915 3B 2323
```

| 字段 | 值 | 解析 |
|------|-----|------|
| 帧头 | `40 40` | |
| 流水号 | `7D 06` | 0x067D = 1661 |
| 时间标签 | `22 11 0D 0A 09 15` | 21年9月10日13:17:34 |
| 源地址 | `02 00 00 00 00 00` | |
| 目的地址 | `00 00 00 00 00 00` | |
| 数据长度 | `30 00` | 0x0030 = 48字节 |
| 命令字 | `02` | 发送数据 |
| **应用数据** | | |
| 类型+数目 | `02 01` | 类型=2(部件运行状态), 信息数=1 |
| 系统类型 | `01` | 火灾报警系统 |
| 系统地址 | `03` | 系统地址=3 |
| 保留位 | `00` | |
| 部件地址 | `50 01 01 00` | 0x00010150 = 小端 → 回路1+地址336 |
| 运行状态 | `05 00` | = 0x0000000000000101 |
| 部件说明 | `00` + 30B | 说明+填充 |
| 时间 | `22 11 0D 0A 09 15` | BCD = 21年9月10日13:17:34 |
| 校验和 | `3B` | |
| 帧尾 | `23 23` | |

### 地址格式（6种编码方式）

| 编码 | 说明 |
|------|------|
| 1 | 部件地址0(回路号) + 部件地址1 + 部件地址2(地址号) + 部件地址3（部件地址0+1拼成10进制为回路号，部件地址2+3拼成10进制为地址号） |
| 2 | 部件地址0..3（4字节解析为1个10进制地址号） |
| 3 | 部件地址0(回路号) + 1 + 2(地址号) + 3 |
| 4 | 系统地址(楼栋) + 部件地址0(区) + 部件地址1(楼) + 部件地址2(层) + 部件地址3 |
| 5 | 系统地址(楼栋) + 部件地址0(设备码) + 部件地址1(户码) |
| 6 | 部件地址0~3(点位号) |

## 六、本项目实现范畴

本网关充当 **监控中心（TCP Server）** 角色：

- 监听端口，接受传输装置 TCP 连接
- 接收各类上传报文，解析后回复确认/否认
- 将数据转换为 PointData 发布到内部总线

### 实现范围

1. **帧解析（上行）**：解析 `40 40 ... 23 23` 帧，验证校验和，提取控制单元+应用数据单元
2. **帧构建（下行）**：确认（命令字3）/ 否认（命令字6），控制命令（命令字1）/ 请求（命令字4）
3. **数据解析**：
   - 系统状态 ← 类型标志 1
   - 部件运行状态 ← 类型标志 2
   - 模拟量值 ← 类型标志 3
   - 传输装置运行状态 ← 类型标志 21
   - 操作信息 ← 类型标志 4/24
4. **命令下发**：
   - 查询命令（类型 61~68, 81~88）
   - 时间同步（类型 90）
   - 初始化（类型 89）、查岗（类型 91，）

### 设计决策

| 决策项 | 方案 |
|--------|------|
| 角色定位 | 监控中心（TCP Server），被动接收报警数据 |
| 连接模型 | `map[string]*Connection` 管理多装置（以源地址为 key） |
| 字节序 | 多字节字段均为 **低字节在前/大端** |
| 校验和 | 控制单元(第3~27字节) + 应用数据单元的算术和，模256 |
| 地址格式 | 标准 6 字节，但部件地址解析需支持多种编码方式 |
| 字符串编码 | GB 18030-2005（兼容 GBK/GB2312） |
| 行容差 | CSV 解析跳过错误行，继续使用正常行 |

## 八、风险点

1. **XML 扫描件不够清晰**：部分数据结构的精确字节定义基于扫描件 OCR 推断，可能存在偏移
2. **地址格式**：标准定义了 6 种编码方式但报文只展示了其中部分，实际可能有更多变种
3. **字段为空**：某些类型标志对应的数据单元"可为空"，需确认确认/否认/否认包的基础结构
4. **GB18030 中文编码处理**：例如描述字段需要正确处理多/ 双字节字符
5. **UDP 模式**：帧结构表备注"UDP 方式发送时可忽略确认/否认"，严格限制需要 TCP/UDP 都支持
6. **目的地地**：当前案例中目的地址为 `000000000000`，可能是"不指定"或"广播"的语义
